# SEO & performance

Next.js 16 App Router in `nextjs/`. Read `nextjs/node_modules/next/dist/docs/` before using an unfamiliar API (`params` is a Promise, `priority` is deprecated in favour of `preload`/`loading="eager"`, and `PageProps<'/route'>` is global after `next typegen`).

## Every new route

1. Server Component page and `pageMetadata({ title, description, path, image? })` from `lib/seo.ts`, which gives a canonical plus OG and Twitter tags.
2. `breadcrumbJsonLd([...])` and a visible breadcrumb via `PageIntro crumbs`.
3. Add it to `app/sitemap.ts`. Dynamic routes map their data.
4. Link it from the nav, footer or a contextual CTA with `next/link`, so no page is orphaned.
5. Moving a URL? Add a permanent redirect in `next.config.ts` `legacyRedirects`.

## Structured data (truthful only)

Site-wide: Organization (TarunSpeaks), Person (founder), WebSite. Per page: BreadcrumbList; `ItemList` of `Course` on /programs; `Article` on case studies; `FAQPage` on /contact. **Never** Review, AggregateRating, or offers and prices that aren't published.

## Performance budget

- Client components stay small and leaf-level (Navbar, MobileMenu, Counter, Journey, ProgramIndex, InsightGrid, EnquiryForm, Chatbot, RevealObserver). Pages and sections are server-rendered.
- Images: `Photo` (next/image) with accurate `sizes`. Only the first-viewport image gets `preload`/`loading="eager"`/`fetchPriority="high"`.
- Fonts: `next/font` (Archivo variable with `wdth`, Inter), `display: swap`.
- No GSAP or Lenis. Before adding any dependency, check whether CSS or Motion already does the job.
- OG image is a static `app/opengraph-image.png` (1200×630), regenerated by script, not rendered at runtime.

## Verify

`npx tsc --noEmit`, `npx eslint`, `npx next build`, then `visual-qa` (it checks canonical, h1, JSON-LD, sitemap, robots and redirects).
